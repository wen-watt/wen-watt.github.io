Wen Open Lab: Ten Walkthroughs, Two New Models and 37 Checks

October 27, 2026

Almanac guide Written by the almanac itself. Every claim links to a source you can open or to a model you can run and check.

The Wen story is a journey: a poem, a trillion tokens, a million wallets, an open NFT standard, and then a Lab that turns all of it into tools anyone can test. Today the Lab gets its biggest note so far. Ten walkthroughs explain, in plain words, what Solana's Token-2022 can do for people, shops, creators and machines, and two new models join the code: a receipt verifier and a token inspector. All 37 checks pass.

The ten, in one line each

  1. A warranty card that lives in the wallet. Did you know? A warranty card can live in your wallet and refuse to be resold.
  2. A payment that needs an invoice number. Did you know? A payment can refuse to arrive without an invoice number.
  3. A royalty rule inside the NFT. Did you know? An NFT can carry its royalty rule inside the token.
  4. One reference key per order. Did you know? A small shop can match every payment to its order with no customer data.
  5. Testing Token-2022 with no network. Did you know? A whole Solana runtime can run inside a test, in milliseconds.
  6. Card fees and on-chain fees, in five formulas. Did you know? On-chain, the network fee is usually the smallest part of the cost.
  7. Checking a warranty card like a machine. Did you know? A repair shop can verify a warranty card in one second, from public data only.
  8. Reading any token like an auditor. Did you know? Some tokens let one key move or burn tokens from any holder.
  9. A devnet run anyone can repeat. Did you know? You can repeat the Lab's models on a public network with a wallet that holds nothing of value.
  10. Search the address, not the name. Did you know? Anyone can create a token with the same name, ticker and logo as a real one.

Each walkthrough on the Lab note shows the key lines of code, the test that proves them, who gains and where the model stops.

Did you know? · WenWEN is tied to the Wen New Standard (WNS): an open way to build NFTs on Solana's Token-2022, with royalties enforced by the token itself. Token-2022 and WNS →

What is new in the code

  • Model 5 · receipt verifier (05-verify-receipt.ts): eight checks from public data, and six test scenarios that try to fool it, from a forged order to an expired warranty.
  • Model 6 · token inspector (06-inspect-mint.ts): who can still mint, freeze or move tokens, and what each Token-2022 extension means for a holder.
  • 37 checks now run in LiteSVM, a local Solana VM: see the full log.

Why it all leads back to Wen

Every one of the ten walkthroughs uses tools that anyone may use, and every one of them traces back to the same source. WNS, the open NFT standard on Token-2022, came out of the Wen community; its code is open in the Wen Program Library under Apache-2.0; and WEN itself is one public address that anyone can check. Wen is universal because it was opened for everyone, not built for a few. The Lab only follows that path.

Why it matters

Usefulness is measured by what people can do that they could not do before. A buyer keeps a warranty that cannot be forged. A bookkeeper gets payments that carry their invoice numbers. A creator keeps a rule that travels with the work. A small shop matches payments without collecting personal data. A holder sees, in plain words, the powers behind a token before receiving it. None of it needs a price, a promise or a paid tool.

What comes next

The ten walkthroughs are being written out in full for developers on dev.to and Hashnode, one at a time; four are already published and linked from the Lab note. The sources page will gather them as they appear.
