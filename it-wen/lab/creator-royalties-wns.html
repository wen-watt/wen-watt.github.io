Per anni le royalty sugli NFT sono dipese dalla voglia di un marketplace di pagarle. WNS ha spostato questa regola dentro il token: un transfer hook viene eseguito a ogni trasferimento e fa rispettare la quota del creatore. Questo modello mostra come vedere quale programma protegge un NFT e come spostare l'NFT in modo che quella protezione venga davvero eseguita.

Il compito

Assicurarsi che un creatore riceva la sua quota a ogni rivendita, che l'NFT sia venduto su un grande marketplace, su uno piccolo o passato direttamente tra portafogli.

Il modello

  1. Un mint NFT porta l'estensione Token-2022 Transfer Hook, che indica un programma hook. Per gli asset WNS quel programma è la distribuzione royalty di WNS: diste3nXmK7ddDTs1zb6uday6j4etCa9RChD8fJ1xay.
  2. A ogni trasferimento, Token-2022 chiama l'hook. Se le condizioni dell'hook non sono soddisfatte, l'intera transazione viene annullata.
  3. L'hook ha bisogno di account aggiuntivi. L'helper ufficiale createTransferCheckedWithTransferHookInstruction li legge dalla catena, così portafogli e marketplace non devono indovinare.

Il codice

File: lab/code/src/02-royalty-transfer.ts · Apache-2.0

// Model 2: creator royalties. Inspect which program enforces royalties on an NFT,
// then transfer it so that the transfer hook (e.g. WNS royalty distribution) runs.
// License: Apache-2.0. Example code, not audited. Devnet first.
import { PublicKey, Transaction, sendAndConfirmTransaction } from '@solana/web3.js';
import {
  TOKEN_2022_PROGRAM_ID, createAssociatedTokenAccountIdempotentInstruction,
  createTransferCheckedWithTransferHookInstruction, getAssociatedTokenAddressSync, getMint, getTransferHook,
} from '@solana/spl-token';
import { WNS_ROYALTY_PROGRAM_ID, detectTokenProgram, getConnection, loadKeypair } from './common.js';

/** Read the transfer-hook program attached to a mint. */
export async function inspectRoyaltyHook(mintAddress: string) {
  const connection = getConnection();
  const mint = new PublicKey(mintAddress);
  const program = await detectTokenProgram(connection, mint);
  if (!program.equals(TOKEN_2022_PROGRAM_ID)) return { mint: mintAddress, hook: null, note: 'Classic SPL token: no transfer hooks' };
  const info = await getMint(connection, mint, 'confirmed', TOKEN_2022_PROGRAM_ID);
  const hook = getTransferHook(info);
  const hookProgram = hook?.programId ?? null;
  return {
    mint: mintAddress,
    hook: hookProgram?.toBase58() ?? null,
    isWnsRoyalty: hookProgram ? hookProgram.equals(WNS_ROYALTY_PROGRAM_ID) : false,
  };
}

/** Transfer one NFT. The helper resolves the hook's extra accounts on-chain, so royalties logic runs. */
export async function transferWithRoyalties(mintAddress: string, to: string) {
  const connection = getConnection();
  const owner = loadKeypair();
  const mint = new PublicKey(mintAddress);
  const recipient = new PublicKey(to);
  const source = getAssociatedTokenAddressSync(mint, owner.publicKey, false, TOKEN_2022_PROGRAM_ID);
  const destination = getAssociatedTokenAddressSync(mint, recipient, false, TOKEN_2022_PROGRAM_ID);

  const transferIx = await createTransferCheckedWithTransferHookInstruction(
    connection, source, mint, destination, owner.publicKey, 1n, 0, [], 'confirmed', TOKEN_2022_PROGRAM_ID,
  );
  const tx = new Transaction().add(
    createAssociatedTokenAccountIdempotentInstruction(owner.publicKey, destination, recipient, mint, TOKEN_2022_PROGRAM_ID),
    transferIx,
  );
  // If the hook rejects the transfer (for example, royalties not approved), the whole transaction rolls back.
  return sendAndConfirmTransaction(connection, tx, [owner]);
}

// Example: npx tsx src/02-royalty-transfer.ts <MINT_ADDRESS>
if (process.argv[2]) inspectRoyaltyHook(process.argv[2]).then(r => console.log(r)).catch(e => { console.error(e); process.exit(1); });

Cosa è stato verificato

In LiteSVM: viene creato un mint NFT con un transfer hook che punta al programma royalty di WNS, e la logica di ispezione rilegge correttamente quel programma dal mint. La funzione di trasferimento è controllata nei tipi rispetto all'API ufficiale @solana/spl-token; eseguirla dall'inizio alla fine richiede i veri programmi WNS, compito della fase devnet nella roadmap.

Dove è utile

  • Arte digitale, musica e NFT video.
  • Oggetti di gioco i cui designer guadagnano dal mercato secondario.
  • Collezionabili di marchi su licenza, dove la royalty di licenza segue ogni vendita.

Limiti e rischi

  • L'hook vede il numero di token spostati, non il prezzo. Una vendita regolata in una transazione separata («un regalo per 0 SOL») può aggirare una royalty in percentuale. WNS gestisce questo caso con una logica di approvazione; leggi il programma prima di farci affidamento.
  • Ogni chiamata all'hook costa unità di calcolo. Gli aggregatori potrebbero doverne richiedere di più.
  • L'audit di WNS è documentato come non completato formalmente. Tienine conto.
