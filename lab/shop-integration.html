We went the other way round. First came the long work: six Token-2022 models, the payments bridge, the cost simulator, the receive-only till with 57 open checks, translations into four languages. Only then the short part: a WooCommerce plugin and a skill that an AI assistant can follow to put the same checkout into a real shop. Free, forever: no fee, no subscription, nobody in the middle.

Where shops live

Before building, we checked which platforms shops actually run on. WooCommerce and Shopify are far ahead of everyone else, so the first plugin is for WooCommerce, the most installed one, and the skill covers the rest with links, buttons and the hosted till.

The WooCommerce plugin: Wen Counter Pay

  1. The buyer places the order and chooses Pay with Solana Pay, in the classic checkout or the Checkout block.
  2. The order gets a fresh reference key and a Solana Pay link: the shop's address, the amount in USDC or another token, and order:<number> as memo.
  3. The buyer pays from their own wallet by QR or the Open in wallet button.
  4. The shop server reads the chain (three read methods only) and runs the five-point check: reference, recipient, token, amount, success. Then the order is paid. One transaction pays one order.
  5. Closed the tab? A background check every five minutes finishes the job for 24 hours.

The skill: an AI assistant that installs it the safe way

A skill is a short instruction file, SKILL.md, that assistants such as Claude Code, Codex, Cursor or Copilot can load. Ours tells the assistant to audit the shop first, pick the right path, paste only the public receiving address, test on devnet, verify the build and report back. It also tells the assistant what never to do: ask for a seed phrase, connect a wallet, or switch to mainnet without the owner.

Open SKILL.md · shop audit checklist · security review · sources and foundations

Honest limits

  • The buyer needs a Solana wallet with funds. No code removes that.
  • One receiving address per shop in the plugin; several wallets per department live in the in-person till.
  • Refunds are new payments from the owner's wallet; there are no chargebacks.
  • Shopify, Wix and Squarespace orders are not marked paid automatically yet; the skill says so to the owner.
  • Example code, not audited. Devnet first. The shop owner is responsible for the shop, receipts and taxes.

Open use policy

  • Free and open. All Lab code is released under the Apache License 2.0, the same license as the Wen Program Library. Use it, change it, ship it, commercially or not; keep the license notice.
  • Open tools only. Built on public, documented tools: Solana SPL Token-2022 (Token Extensions), the token layout of the Wen New Standard (WNS), Solana Pay, and LiteSVM for local testing.
  • The rule: always verify your own model. Run the tests, start on devnet, read the official documentation, review every account and amount, and get an independent audit before any mainnet use. A model that is not checked is not a model, it is a guess.
  • Not audited, not advice. These are educational examples. They are not financial, legal or tax advice, and not a licensed payment or banking product. Payments, stablecoins and acquiring are regulated activities in most countries.
  • Security. Never paste a private key into a website. Do not install the npm package @wen-community/wen-new-standard: npm removed it as malicious. Build from official sources.
