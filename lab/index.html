Knowing what Wen is was the first step. The Lab is the second: we take the open tools behind Wen — the WNS token layout, Solana Token-2022 and Solana Pay — and build free, working models that a developer, a shop, a fintech team or a bank can study, test and reuse. Everything is open, step by step, in public.

Why this exists

The almanac explains Wen in depth: the poem, the airdrop, the WNS standard, the link with Jupiter and Solana. But description alone is not utility. Utility starts when someone can take a model, run it, check it and build on it. The Lab does exactly that, and does it in the open, so that the value of Wen's technical heritage is shared freely rather than locked away.

ALL CHECKS PASSED

Two real pitfalls were found while building, which is exactly why the rule is "verify your own model": the npm package @wen-community/wen-new-standard has been removed as malicious, and recent versions of @solana/spl-memo point to a different memo program than the canonical one Token-2022 checks. Both are handled in the code.

Run it yourself

# get the files from lab/code/ (package.json, tsconfig.json, src/, test/)
npm install
npm run typecheck   # TypeScript, strict mode
npm test            # local Solana VM, no network, no real funds

For devnet: create a wallet with the Solana CLI, request devnet SOL, then set KEYPAIR and optionally RPC_URL before calling the send functions in each file. Start with a fresh, empty wallet.

Open use policy

  • Free and open. All Lab code is released under the Apache License 2.0, the same license as the Wen Program Library. Use it, change it, ship it, commercially or not; keep the license notice.
  • Open tools only. Built on public, documented tools: Solana SPL Token-2022 (Token Extensions), the token layout of the Wen New Standard (WNS), Solana Pay, and LiteSVM for local testing.
  • The rule: always verify your own model. Run the tests, start on devnet, read the official documentation, review every account and amount, and get an independent audit before any mainnet use. A model that is not checked is not a model, it is a guess.
  • Not audited, not advice. These are educational examples. They are not financial, legal or tax advice, and not a licensed payment or banking product. Payments, stablecoins and acquiring are regulated activities in most countries.
  • Security. Never paste a private key into a website. Do not install the npm package @wen-community/wen-new-standard: npm removed it as malicious. Build from official sources.
