Wen began as a poem split into a trillion tokens and grew into WNS, an open NFT standard on Solana's Token-2022. The Lab turns that heritage into small, tested tools. Wen was not made for a few: its standard, its code and its story are open to everyone, and every walkthrough below leads back to that source. This note gathers them into ten walkthroughs: each one starts with a "did you know", shows the few lines of code that matter, the test that proves them, who gains, and where the model stops. Two models are new today: a receipt verifier and a token inspector. 37 checks pass.

1 · A warranty card that lives in the wallet

Did you know? · WenA warranty card can live in your wallet and refuse to be resold.

Paper cards get lost and PDF receipts sink in an inbox. Token-2022 turns a purchase into a one-of-one token: zero decimals, supply locked at 1, the details stored inside the mint itself, and the NonTransferable extension so the warranty stays with the buyer. The chain keeps only a SHA-256 hash of the order, never the order: the buyer keeps the JSON and can prove the match later. It is the same light-NFT layout the Wen New Standard (WNS) uses.

The Wen thread. The layout is the Wen New Standard's: the same light NFT that WNS, born in the Wen community, put on Token-2022. Wen opened it for everyone, so a shop's receipt can use it as freely as a meme.

createInitializeNonTransferableMintInstruction(mint, TOKEN_2022_PROGRAM_ID),
createInitializeMintInstruction(mint, 0, merchant, null, TOKEN_2022_PROGRAM_ID),
// ... metadata fields: order_hash, warranty_until, sku

Useful for

  • Buyers: a warranty that cannot be lost or forged with an edited PDF.
  • Shops: proof of purchase without storing personal data on a public ledger.

Limits, stated plainly

  • The token is a proof; warranty terms still follow the shop's policy and consumer law.
  • Soulbound is not unlosable: a lost wallet loses the card, and the shop reissues it after its own checks.

2 · A payment that needs an invoice number

Did you know? · WenA payment can refuse to arrive without an invoice number.

Accountants lose hours matching payments that arrive without a reference. Three Token-2022 extensions turn a plain token into a settlement rail with rules: the receiving account demands a memo (MemoTransfer), every new account starts frozen until the issuer approves it (DefaultAccountState), and a capped percentage fee is withheld by the token program itself (TransferFeeConfig). No custom on-chain program is needed. The memo must be the instruction right before the transfer.

The Wen thread. WNS showed that rules can live inside the token, not in each app. The invoice rail takes the same idea from the Wen community to bookkeeping: the token itself refuses a payment without a number.

Key lines · lab/code/src/03-b2b-invoice.ts · Apache-2.0

export function buildPayInvoice(args) {
  return [
    ...(args.invoiceId ? [memoInstruction(`invoice:${args.invoiceId}`, args.payer)] : []),
    createTransferCheckedWithFeeInstruction(args.from, args.mint, args.to, args.payer,
      args.amount, DECIMALS, expectedFee(args.amount), [], TOKEN_2022_PROGRAM_ID),
  ];
}

How it was checked

PASS  M3 payment WITHOUT invoice number is rejected
PASS  M3 payment to a NOT approved company is rejected (account frozen)
PASS  M3 fee cap works (fee on 100,000 is 50, not 250)

Useful for

  • Bookkeeping: every payment carries its invoice number on-chain.
  • Business networks: only approved counterparties can hold the token.

Limits, stated plainly

  • A memo is public: an invoice number, never names or personal details.
  • A real settlement token is issued by a licensed entity; this is a model, not a stablecoin.

3 · A royalty rule inside the NFT

Did you know? · WenAn NFT can carry its royalty rule inside the token.

A Token-2022 mint can carry a TransferHook: the address of a program that runs on every transfer, in every wallet and marketplace. If the program says no, the transfer does not happen. WNS uses this for creator royalties. The walkthrough shows the step every buyer and wallet should take first: read the hook, and also read its authority, because the authority decides who can change the rule tomorrow. Moving a hooked token needs TransferChecked with the hook's extra accounts.

The Wen thread. This is where Wen began technically: WNS enforces creator royalties with a transfer hook. The code uses the WNS royalty program address published in the open Wen Program Library.

Key lines · lab/code/src/02-royalty-transfer.ts · Apache-2.0

const info = await getMint(connection, mint, 'confirmed', TOKEN_2022_PROGRAM_ID);
const hook = getTransferHook(info);          // { programId, authority }
const isWnsRoyalty = hook?.programId.equals(WNS_ROYALTY_PROGRAM_ID) ?? false;

// transfer so that the hook runs: extra accounts are resolved on-chain
const ix = await createTransferCheckedWithTransferHookInstruction(
  connection, source, mint, destination, owner.publicKey, 1n, 0, [], 'confirmed', TOKEN_2022_PROGRAM_ID);

How it was checked

PASS  M2 NFT mint created with a transfer hook
PASS  M2 hook program read from the mint = WNS royalty distribution

Useful for

  • Creators: a rule that travels with the work, not a promise from each marketplace.
  • Buyers and agents: the rule is machine-readable in one RPC call.

Limits, stated plainly

  • The local test reads the hook; the WNS royalty program itself is not executed in the local VM.
  • A hook enforces whatever its program says, mistakes included: read the code and audits.

4 · One reference key per order

Did you know? · WenA small shop can match every payment to its order with no customer data.

Solana Pay gives each order a fresh random reference key. The wallet adds it to the transfer as a read-only account, so the shop can find the transaction by that key, then validate recipient, amount, token, reference and memo before marking the order paid. Finding is not trusting: findReference only says a transaction mentions the key; validateTransfer checks the money. A webhook then tells the shop's own system, the role a card acquirer's callback plays.

The Wen thread. A Solana Pay link works for any token, and the Lab's code lists WEN by its one real address. The rule that comes from Wen applies here too: the shop checks the address, never the name.

Key lines · lab/code/src/04-solana-pay-bridge.ts · Apache-2.0

const reference = (await generateKeyPairSigner()).address;   // random, never reused
const url = encodeURL({ recipient, amount, splToken, reference,
  label: 'Wen Open Lab demo shop', message: `Order ${orderId}`, memo: `order:${orderId}` });
// later
const found = await findReference(rpc, req.reference, { commitment: 'confirmed' });
await validateTransfer(rpc, found.signature, { recipient, amount, splToken, reference, memo }, { commitment: 'confirmed' });

How it was checked

PASS  M4 payment link round-trips: recipient, amount, token, reference, memo
PASS  M4 every order gets a unique reference

Useful for

  • Small sellers: reconciliation without a processor account.
  • Customers: no card number and no personal data go to the shop's server.

Limits, stated plainly

  • A shop that needs stable amounts should accept a stable asset; the model converts nothing.
  • Refunds, disputes and taxes stay the shop's responsibility.

5 · Testing Token-2022 with no network

Did you know? · WenA whole Solana runtime can run inside a test, in milliseconds.

LiteSVM loads the real SPL Token-2022 and Memo programs into the test process. The Lab's harness is five helpers: send, fund, rent, account and check. One decoder bridges @solana/web3.js transactions to LiteSVM, the blockhash is expired after every send so repeated steps stay independent, and failures come back as values with their logs. The useful tests are the ones that expect a refusal and check the program log that explains it.

The Wen thread. Wen's launch was a public stress test that Solana passed. Testing in public, then repeating it, is the habit the Lab keeps from that day.

Key lines · lab/code/test/run-litesvm.ts · Apache-2.0

function send(ixs, signers) {
  const tx = new Transaction().add(...ixs);
  tx.feePayer = signers[0].publicKey;
  tx.recentBlockhash = svm.latestBlockhash();
  tx.sign(...signers);
  const res = svm.sendTransaction(getTransactionDecoder().decode(tx.serialize()));
  svm.expireBlockhash();
  return res instanceof FailedTransactionMetadata
    ? { ok: false, err: res.toString(), logs: res.meta().logs() } : { ok: true, logs: res.logs() };
}

Useful for

  • Developers: a fast test loop for Token-2022 without airdrops or rate limits.

6 · Card fees and on-chain fees, in five formulas

Did you know? · WenOn-chain, the network fee is usually the smallest part of the cost.

The Lab simulator compares card acquiring and on-chain payments with five public formulas and runs in the browser. With illustrative inputs (2,000 orders a month, $40 average, 2.9% + $0.30 card price, 0.5% chargebacks at $15, two settlement days) the card side costs about $3,470 a month and keeps about $5,333 in transit. On the on-chain side the network part is 0.02 SOL for the whole month, and almost the entire cost is the 0.5% conversion to fiat: $400. The point is not who wins; it is where the cost actually sits.

The Wen thread. If a shop ever accepts WEN, the simulator says it plainly: WEN brings community and attention to the checkout, stable amounts belong to stablecoins. Usefulness first, no promises.

Key lines · the simulator page · Apache-2.0

Revenue                      = orders × average order
Card payment fees            = revenue × card fee % + orders × fixed fee
Chargeback costs             = orders × chargeback rate × (average order + fee per chargeback)
On-chain fees                = orders × network fee in SOL × SOL price + revenue × conversion %
Money waiting for settlement = revenue ÷ 30 × settlement days

How it was checked

formulas shown on the page
calculation runs in the browser, nothing is sent

Useful for

  • Small businesses: a decision from arithmetic, not from adverts.
  • Everyone: a clear list of what the comparison leaves out.

Limits, stated plainly

  • Illustrative defaults, not a quote: use your own contract terms and today's prices.
  • Left out: setup and compliance costs, wallet adoption, the buyer protection that chargebacks give, price movement.

7 · Checking a warranty card like a machine

Did you know? · WenA repair shop can verify a warranty card in one second, from public data only.

New in the Lab: Model 5, the other half of walkthrough 1. A pure function takes the mint and the holder's account and answers eight questions: Token-2022 mint, one of one, soulbound, metadata inside the mint, issued by the expected shop, warranty still valid, order hash matches the buyer's order, held by the expected wallet. It returns every check with its name, so a person at the counter sees "expired" or "issued by someone else", not just "invalid". A thin wrapper reads both accounts in one RPC call.

The Wen thread. The verifier checks exactly the WNS-style card from walkthrough 1. What Wen opened, anyone can now also verify, without asking anyone's permission.

8 · Reading any token like an auditor

Did you know? · WenSome tokens let one key move or burn tokens from any holder.

New in the Lab: Model 6, a read-only inspector for any mint. It tells which program owns the token, who can still mint or freeze, which Token-2022 extensions it carries, and what each one means for a holder in plain words: a permanent delegate that can move or burn anyone's tokens, a transfer fee, a transfer hook and who can change it, accounts that start frozen, soulbound tokens, a mint that can be closed. It refuses wallet addresses instead of misreading them.

The Wen thread. Try it on the real WEN mint, WENWENvqqNya429ubCdR81ZmD69brwQaaBYY6p3LCpk, and read its powers yourself instead of trusting anyone's words, ours included.

Key lines · lab/code/src/06-inspect-mint.ts · Apache-2.0

if (t === ExtensionType.PermanentDelegate) {
  const d = getPermanentDelegate(m);
  notes.push(`Permanent delegate ${d?.delegate.toBase58()}: can transfer or burn tokens from ANY holder.`);

    (h?.authority ? `; authority ${h.authority.toBase58()} can change it.` : '; it cannot be changed.'));
}

9 · A devnet run anyone can repeat

Did you know? · WenYou can repeat the Lab's models on a public network with a wallet that holds nothing of value.

Local tests run on one machine; devnet moves the same instructions onto a public network where every step gets a public link. The Lab's devnet script refuses to run outside devnet, checks the balance of a new, empty wallet, issues a soulbound receipt, then builds the invoice-only settlement token, approves two accounts, pays an invoice with its number and shows that a payment without a number is rejected. Every step prints a Solana Explorer link with ?cluster=devnet.

The Wen thread. The devnet run repeats in public what Wen's launch did on mainnet: ordinary people, one transaction each, and every step visible on an explorer.

10 · Search the address, not the name

Did you know? · WenAnyone can create a token with the same name, ticker and logo as a real one.

The almanac's first safety rule, turned into three checks anyone can do. One: compare the mint address with the official source, character by character; the real WEN is WENWENvqqNya429ubCdR81ZmD69brwQaaBYY6p3LCpk. Two: check which program owns the mint and what powers it carries, with the inspector from walkthrough 8 or on an explorer. Three: no real team, airdrop or support chat ever needs a seed phrase. Names, tickers and pictures are decoration; the address is identity.

The Wen thread. The real WEN is one address: WENWENvqqNya429ubCdR81ZmD69brwQaaBYY6p3LCpk. Wen is open to everyone, which is exactly why copies appear; the address is how the community stays itself.

Key lines · lab/code/src/common.ts · Apache-2.0

export async function detectTokenProgram(connection: Connection, mint: PublicKey): Promise<PublicKey> {
  const info = await connection.getAccountInfo(mint);
  if (!info) throw new Error(`Mint ${mint.toBase58()} not found on this cluster`);
  if (info.owner.equals(TOKEN_2022_PROGRAM_ID)) return TOKEN_2022_PROGRAM_ID;
  if (info.owner.equals(TOKEN_PROGRAM_ID)) return TOKEN_PROGRAM_ID;
  throw new Error(`Account ${mint.toBase58()} is not a token mint`);
}

How it was checked

PASS  M6 a wallet address is refused, not parsed as a mint
the same check runs before every model

Useful for

  • Everyone: a habit that stops the most common token scams.
  • Communities: one address to repeat everywhere, instead of a name that can be copied.

Limits, stated plainly

  • A correct address does not make a token a good idea; it only makes it the real one.
  • Official sources can be impersonated too: cross-check at least two.

What it means: from hidden to open

For people who work with money, code and transactions

For decades the rules of commerce lived out of sight: in a card processor's contract, a marketplace's policy, a back office that matches payments by hand. The ten walkthroughs show the same rules moving into the token itself, where anyone can read them: who may hold it, what a transfer costs, which invoice it pays, who earns a royalty, whether a card is genuine. In the almanac's reading, this is where Wen stops being only a meme and works as a ready, open mechanism: a standard (WNS) that came out of its community, code that anyone may use under Apache-2.0, and one public address to anchor it. What used to be hidden in private systems becomes open, checkable infrastructure. That is a view, not a forecast; the models show the mechanics, and the tests show they work.

For everyone else

You do not need to write code to use what these models describe. The same ideas apply anywhere in the world:

  • Shopping: a receipt and warranty that live in your wallet and cannot be lost or faked.
  • Work and business: payments between companies that always carry their invoice number.
  • Art, music and photos: royalties that travel with the work instead of depending on each platform.
  • Small shops and markets: payments matched to orders with no card numbers and no personal data collected.
  • Everyday safety: checking a token by its address and reading its powers before you trust it.

Why Wen is unique. Wen began as a poem shared with more than a million wallets, not as a product sold to them. Its standard was proposed in public and its code is open to everyone; its launch was a live test that Solana passed in front of all; and the one real WEN is a single address anyone can check. Many tokens have a story. Wen left something everyone can use, which is why every walkthrough here leads back to it.

Where Wen fits in this model
