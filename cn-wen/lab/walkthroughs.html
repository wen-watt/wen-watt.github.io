1 · 住在钱包里的保修卡

你知道吗？· Wen保修卡可以住在你的钱包里，并拒绝被转卖。

纸质保修卡会丢，PDF 收据会淹没在收件箱里。Token-2022 把一次购买变成独一无二的代币：零位小数、供应量锁定为 1、细节存放在铸币本身之中，再加上 NonTransferable 扩展让保修留在买家手中。链上只保存订单的 SHA-256 哈希，从不保存订单本身：买家保留 JSON，之后可以证明二者匹配。这与 Wen New Standard（WNS）所用的轻量 NFT 布局相同。

Wen 的主线。这个布局来自 Wen New Standard：诞生于 Wen 社区的 WNS 放到 Token-2022 上的同一种轻量 NFT。Wen 把它开放给所有人，所以商店的收据可以像梗一样自由地使用它。

关键代码 · lab/code/src/01-receipt-nft.ts · Apache-2.0

// extensions first, then the mint, then the metadata
createInitializeMetadataPointerInstruction(mint, merchant, mint, TOKEN_2022_PROGRAM_ID),
createInitializeNonTransferableMintInstruction(mint, TOKEN_2022_PROGRAM_ID),
createInitializeMintInstruction(mint, 0, merchant, null, TOKEN_2022_PROGRAM_ID),
// ... metadata fields: order_hash, warranty_until, sku
createMintToInstruction(mint, buyerAta, merchant, 1, [], TOKEN_2022_PROGRAM_ID),
// lock supply at exactly 1
createSetAuthorityInstruction(mint, merchant, AuthorityType.MintTokens, null, [], TOKEN_2022_PROGRAM_ID),

PASS  M1 supply is exactly 1, decimals 0, mint authority removed
PASS  M1 soulbound receipt cannot be transferred
PASS  M1 nobody can mint a second copy

适用于

  • 买家：不会丢失、也无法用篡改的 PDF 伪造的保修。
  • 商店：无需在公共账本上保存个人数据的购买凭证。

局限，坦白说明

  • 代币只是证明；保修条款仍遵循商店政策和消费者法律。
  • 灵魂绑定不等于不会丢：钱包丢了，保修卡也就丢了，商店会在自行核查后补发。

2 · 需要发票号的付款

你知道吗？· Wen没有发票号，付款可以拒绝到账。

会计要花好几个小时去匹配没有参考号的付款。三个 Token-2022 扩展把普通代币变成带规则的结算轨道：收款账户要求备注（MemoTransfer），每个新账户初始冻结、直到发行方批准（DefaultAccountState），代币程序本身预扣有上限的比例手续费（TransferFeeConfig）。不需要任何自定义链上程序。备注必须是紧挨在转账之前的那条指令。

Wen 的主线。WNS 证明了规则可以存在于代币之中，而不是每个应用里。发票轨道把这个来自 Wen 社区的想法带到了记账：代币本身就会拒绝没有编号的付款。

关键代码 · lab/code/src/03-b2b-invoice.ts · Apache-2.0

export function buildPayInvoice(args) {
  return [
    ...(args.invoiceId ? [memoInstruction(`invoice:${args.invoiceId}`, args.payer)] : []),
    createTransferCheckedWithFeeInstruction(args.from, args.mint, args.to, args.payer,
      args.amount, DECIMALS, expectedFee(args.amount), [], TOKEN_2022_PROGRAM_ID),
  ];
}

如何验证

PASS  M3 payment WITHOUT invoice number is rejected
PASS  M3 payment to a NOT approved company is rejected (account frozen)
PASS  M3 fee cap works (fee on 100,000 is 50, not 250)

适用于

  • 记账：每笔付款都在链上带着发票号。
  • 商业网络：只有获批的交易对手才能持有该代币。

局限，坦白说明

  • 备注是公开的：只写发票号，绝不写姓名或个人信息。
  • 备注规则只检查备注是否存在，不检查编号是否正确：请把每笔付款与你的发票对账（读者修正，11 月 9 日）。
  • 真正的结算代币由持牌机构发行；这只是一个模型，不是稳定币。

3 · NFT 里的版税规则

你知道吗？· WenNFT 可以把版税规则装在代币里。

Token-2022 铸币可以带有 TransferHook：一个程序地址，在每个钱包和市场的每次转移时都会运行。如果程序说不，转移就不会发生。WNS 用它来实现创作者版税。导读展示了每个买家和钱包都应该先做的一步：读取钩子，同时读取它的权限，因为权限决定了明天谁能修改规则。转移带钩子的代币需要使用 TransferChecked 并附上钩子的额外账户。

Wen 的主线。这正是 Wen 在技术上的起点：WNS 用转账钩子执行创作者版税。代码使用开放的 Wen Program Library 中公布的 WNS 版税程序地址。

关键代码 · lab/code/src/02-royalty-transfer.ts · Apache-2.0

const info = await getMint(connection, mint, 'confirmed', TOKEN_2022_PROGRAM_ID);
const hook = getTransferHook(info);          // { programId, authority }
const isWnsRoyalty = hook?.programId.equals(WNS_ROYALTY_PROGRAM_ID) ?? false;

// transfer so that the hook runs: extra accounts are resolved on-chain
const ix = await createTransferCheckedWithTransferHookInstruction(
  connection, source, mint, destination, owner.publicKey, 1n, 0, [], 'confirmed', TOKEN_2022_PROGRAM_ID);

如何验证

PASS  M2 NFT mint created with a transfer hook
PASS  M2 hook program read from the mint = WNS royalty distribution

适用于

  • 创作者：一条随作品流转的规则，而不是每个市场的承诺。
  • 买家和代理：一次 RPC 调用就能机器读取这条规则。

局限，坦白说明

  • 本地测试读取钩子；WNS 版税程序本身不在本地虚拟机中执行。
  • 钩子执行它的程序所说的一切，包括错误：请阅读代码和审计报告。

4 · 每笔订单一个参考密钥

你知道吗？· Wen小商店不需要顾客数据，就能把每笔付款和订单对上。

Solana Pay 为每笔订单生成一个新的随机 reference 密钥。钱包把它作为只读账户加入转账，商店就能凭这个密钥找到交易，然后在把订单标记为已付款之前校验收款方、金额、代币、参考号和备注。找到不等于信任：findReference 只说明某笔交易提到了这个密钥；validateTransfer 才检查钱。随后 webhook 通知商店自己的系统，起到银行卡收单回调的作用。

Wen 的主线。Solana Pay 链接适用于任何代币，实验室代码按 WEN 唯一的真实地址列出它。来自 Wen 的规则在这里同样适用：商店核对地址，绝不核对名字。

const reference = (await generateKeyPairSigner()).address;   // random, never reused
const url = encodeURL({ recipient, amount, splToken, reference,
  label: 'Wen Open Lab demo shop', message: `Order ${orderId}`, memo: `order:${orderId}` });
// later
const found = await findReference(rpc, req.reference, { commitment: 'confirmed' });
await validateTransfer(rpc, found.signature, { recipient, amount, splToken, reference, memo }, { commitment: 'confirmed' });

如何验证

PASS  M4 payment link round-trips: recipient, amount, token, reference, memo
PASS  M4 every order gets a unique reference

适用于

  • 小卖家：无需支付处理商账户即可对账。
  • 顾客：没有卡号，也没有个人数据进入商店服务器。

局限，坦白说明

  • 需要稳定金额的商店应接受稳定资产；该模型不做任何兑换。
  • 退款、纠纷和税务仍由商店负责。

6 · 五个公式看懂银行卡费用与链上费用

你知道吗？· Wen在链上，网络费通常是成本中最小的部分。

实验室的模拟器用五个公开公式比较银行卡收单和链上支付，在浏览器中运行。用示意数据（每月 2,000 笔订单、平均 40 美元、银行卡 2.9% + 0.30 美元、0.5% 拒付且每笔 15 美元、两天结算），银行卡这边每月约花 3,470 美元，约有 5,333 美元在途。链上这边，整月网络费只有 0.02 SOL，几乎全部成本是 0.5% 的法币兑换：400 美元。重点不在谁赢，而在成本究竟在哪里。

Wen 的主线。如果商店接受 WEN，模拟器会直说：WEN 为收银台带来社区和关注，稳定金额属于稳定币。实用第一，不做承诺。

关键代码 · 模拟器页面 · Apache-2.0

Revenue                      = orders × average order
Card payment fees            = revenue × card fee % + orders × fixed fee
Chargeback costs             = orders × chargeback rate × (average order + fee per chargeback)
On-chain fees                = orders × network fee in SOL × SOL price + revenue × conversion %
Money waiting for settlement = revenue ÷ 30 × settlement days

7 · 像机器一样核验保修卡

你知道吗？· Wen维修店只凭公开数据，一秒钟就能核验一张保修卡。

实验室新增：模型 5，导读 1 的另一半。一个纯函数接收铸币和持有者账户，回答八个问题：是否为 Token-2022 铸币、是否独一无二、是否灵魂绑定、元数据是否在铸币内、是否由预期商店发行、保修是否仍有效、订单哈希是否与买家订单匹配、是否由预期钱包持有。它返回每项检查及其名称，所以柜台的人看到的是“已过期”或“由他人发行”，而不只是“无效”。一个轻量包装器用一次 RPC 调用读取两个账户。

Wen 的主线。核验器检查的正是导读 1 中的 WNS 风格保修卡。Wen 开放的东西，现在任何人都可以核验，无需任何人许可。

export async function detectTokenProgram(connection: Connection, mint: PublicKey): Promise<PublicKey> {
  const info = await connection.getAccountInfo(mint);
  if (!info) throw new Error(`Mint ${mint.toBase58()} not found on this cluster`);
  if (info.owner.equals(TOKEN_2022_PROGRAM_ID)) return TOKEN_2022_PROGRAM_ID;
  if (info.owner.equals(TOKEN_PROGRAM_ID)) return TOKEN_PROGRAM_ID;
  throw new Error(`Account ${mint.toBase58()} is not a token mint`);
}

这意味着什么：从隐藏到开放

写给与资金、代码和交易打交道的人

几十年来，商业规则一直藏在看不见的地方：在银行卡处理商的合同里，在交易市场的政策里，在手工对账的后台里。这十篇导读展示了同样的规则正在搬进代币本身，任何人都能读到：谁可以持有、转账花多少钱、支付哪张发票、谁获得版税、一张卡是否真实。在年鉴看来，Wen 正是在这里不再只是一个梗，而是作为一个现成的、开放的机制运转：一个出自其社区的标准（WNS），任何人都能按 Apache-2.0 使用的代码，以及一个作为锚点的公开地址。过去藏在私有系统里的东西，变成了开放、可核验的基础设施。这是一种观点，不是预测；模型展示机制，测试证明它们有效。

写给其他所有人

你不需要写代码，也能用上这些模型描述的东西。同样的想法在世界任何地方都适用：

  • 购物：住在你钱包里、不会丢失也无法伪造的收据和保修。
  • 工作与商业：企业之间的付款总是带着发票号。
  • 艺术、音乐和照片：版税随作品流转，而不是取决于每个平台。
  • 小店和集市：付款与订单一一对应，不收集卡号，也不收集个人数据。
  • 日常安全：凭地址核验代币，并在信任它之前读懂它的权限。

为什么 Wen 独一无二。Wen 起初是一首与一百多万个钱包分享的诗，而不是卖给他们的产品。它的标准是公开提出的，代码向所有人开放；它的发行是一场 Solana 当着所有人的面通过的现场测试；而唯一真正的 WEN 是一个任何人都能核对的地址。很多代币都有故事。Wen 留下了人人都能使用的东西，所以这里的每一篇导读都通向它。
